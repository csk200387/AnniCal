# 보안 조치 기록 — 2026-09-16

[최초 보고서](SECURITY_REPORT_2026-09-16.md)의 SEC-01~06에 대한 로컬 코드 수정 및 검증 결과다. 운영 배포와 GitHub 관리 화면 설정은 변경하지 않았다.

## 적용한 변경

피드백 본문 상한은 8,000바이트로 정했다. 기존 5,000바이트 제한을 그대로 강제하면 화면에서 허용하는 한글 메시지 2,000자를 전송할 수 없기 때문이다. 메시지 2,000자·출처 URL 500자 제한은 유지한다.

추가로 피드백 `type`의 상속 속성 허용을 제거했고, 발급하는 GitHub App 설치 토큰을 지정한 저장소 한 개의 Issues 쓰기로 축소했다. Redis·GitHub 요청에는 5초 제한을 적용했다. 요청 IP는 Vercel이 설정한 헤더 또는 직접 연결의 소켓에서만 읽으며, 원문 IP는 Redis로 보내지 않는다.

GitHub Actions `Secret scan`과 Gitleaks pre-commit 설정도 추가했다. CI는 읽기 전용 권한과 자격증명을 남기지 않는 checkout을 사용하고, 버전·SHA-256이 고정된 Gitleaks 바이너리로 이력을 검사한다. 로컬 pre-commit 훅은 설정만 제공했으며 설치하지 않았다. 사용법은 [README](../../README.md#보안-및-운영-제한)에 있다.

## 검증 결과

- **`npm run verify` 통과:** slug 검사, Vue/TypeScript 빌드, API 타입 검사, 11개 테스트 파일의 **113개 테스트** 통과.
- **`npm audit` 취약점 0건:** 개발 의존성을 포함한 전체 검사.
- **독립 Redis 7.4.2 인스턴스 검증:** 저장·외부 TCP 연결을 끈 임시 Unix socket 인스턴스에서 실제 API가 생성한 EVAL 명령을 실행했다. 쿠키에 해당하는 방문자 값과 이벤트를 바꾸어 동시 요청 130개를 보냈고 120개 허용·10개 거절을 확인했다. 초과 요청의 HLL/순위 조회가 수행되지 않았으며 이벤트 키도 생성되지 않았다. 여러 네트워크로 3,000회를 채운 후 새 네트워크 요청도 거절되었고, 차단 상태에서 새 네트워크 제한 키를 생성하지 않았다. 중복 이벤트 단일 집계와 윈도 만료 후 재허용도 확인했다. 실제 운영 Redis에는 접근하지 않았다.
- **브라우저 검증:** 빌드 산출물에 `vercel.json`의 실제 CSP 헤더를 적용한 로컬 HTTP 서버와 Chromium으로 `/`, `/calendar`, `/birthday`, `/popular`, `/export`, `/day/01-01/new-year`를 확인했다. CSP 위반 및 브라우저 실행 오류 0건. 공유 이미지 PNG 다운로드 성공. 별도로 삽입한 인라인 스크립트와 허용되지 않은 출처의 fetch가 차단되는 것을 확인했다. 로컬 API와 Analytics 스크립트는 모의 응답을 사용했으므로 실제 외부 서비스 연동 성공까지 검증한 것은 아니다.
- **Gitleaks 8.30.1 검사:** 전체 refs를 대상으로 한 Git 검사에서 탐지 0건. 도구는 변경분이 있는 96개 커밋을 보고했으며, 최초 감사의 전체 Git 커밋 수 101개와 계산 방식이 다르다. Git ignore 대상 비밀파일을 제외하고 복사한 현재 추적·미추적 파일 검사에서도 탐지 0건.
- `.github/workflows/security.yml`, `.pre-commit-config.yaml`의 YAML 파싱 및 `git diff --check` 통과.
- 로컬 비밀파일 권한 `0600` 재확인.

## 운영 적용 시 확인할 사항

1. 코드와 `vercel.json`은 배포 후 운영에 반영된다. 이번 작업에서는 배포·push를 하지 않았다.
2. Vercel 기본 환경변수 `VERCEL=1`과 플랫폼의 IP 헤더 전달을 유지한다. 다른 프록시로 이전하면 `server/request.ts`의 신뢰 경계를 검토해야 한다. 원본 IP를 확인할 수 없는 요청은 하나의 `unknown` 제한 버킷을 공유한다.
3. 공유 IP의 많은 방문자가 120회/분을 넘으면 통계 집계가 제한될 수 있다. 정상 트래픽을 보며 조정한다. 서버 전체 한도는 여러 IP를 사용하는 공격의 집계 비용도 제한하지만, 모든 네트워크·서버리스 비용을 없애는 DDoS 방어는 아니다. 요청당 Redis EVAL 자체는 수행된다.
4. 파싱된 본문의 크기 검사는 Vercel이 이미 파싱한 비용까지 되돌리지는 못한다. 대규모 요청의 진입 차단은 플랫폼의 요청 크기 제한·WAF 설정과 함께 관리한다.
5. GitHub App 설치가 실제로 비공개 피드백 저장소 한 개에만 허용되는지, 서버 측 secret scanning/push protection과 필수 CI 검사가 활성화되어 있는지는 GitHub 관리 화면에서 확인한다. 추가한 토큰 축소는 설치 권한 전체를 바꾸지는 않는다.
6. CSP는 현재 프로덕션 앱에 필요한 출처를 기준으로 한다. Vercel Preview Toolbar 같은 외부 스크립트를 별도로 켜면 호환성 확인이 필요하다.
7. 파일 권한은 Git으로 전달되지 않는다. 다른 개발 장비에서도 비밀파일 생성 시 `umask 077` 또는 `chmod 600`을 적용한다.

데이터 보강 작업으로 이미 변경되어 있던 기념일 JSON과 관련 도구는 이번 수정에서 편집하지 않았다. 검사 결과는 실행 당시 작업 트리를 기준으로 한다.
